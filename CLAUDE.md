# Teacher Rank — project notes

React + Vite + TypeScript, styled with **Tailwind CSS + DaisyUI v3**. Supabase backend, React Query, react-hook-form + Zod.

## UI conventions

Keep new UI consistent with the existing design language. The sources of truth:

- **Colors** — DaisyUI semantic tokens only (`primary`, `secondary`, `base-100/200/300`, `base-content`, `neutral`, `error/success/warning/info`, plus `-content`/`-focus` variants). Theme palette lives in [`tailwind.config.js`](tailwind.config.js) (`daisyui.themes`). Dark mode is class-based (`darkMode: 'class'` + DaisyUI `data-theme`). **No hex / `gray-*` / `yellow-*` literals in components.** Since the 2026-08 identity pass both themes' neutrals carry a deliberate ≤2–3-point **violet temperature bias** (surfaces, borders, ink) so the system reads as chosen rather than default-gray — keep any new surface/ink values in that family, and never drift it toward actual purple.
- **Elevation (2026-08 premium pass)** — `shadow-sm/md/lg` are overridden in `tailwind.config.js` (`theme.extend.boxShadow`) to layered, theme-tinted shadows driven by the per-theme `--shadow-rgb` triple (violet-950 in light, black in dark; defined ONLY in `daisyui.themes` — the NOTE in `styles.css` explains why a `:root` fallback must never be added: it would tie `[data-theme]` on specificity and silently override dark mode). Keep using the standard `shadow-*` utilities — never raw `box-shadow` hexes or Tailwind's stock black-alpha look; dark-mode separation is carried by borders, not shadows. `.card-hover`'s lift shadow uses the same tint.
- **Buttons** — use the [`Button`](src/components/Button.tsx) primitive, never raw `<button className="btn ...">`. Props: `variant` (`primary|secondary|ghost|outline|error|success|warning|info|neutral|link|default`), `size` (`xs|sm|md|lg`), `block`, `wide`, `circle`, `loading` (renders the spinner + disables + sets `aria-busy`), `touch` (`default|tall`). For an `<a>`/`<Link>` that should look like a button, use `buttonClasses({ variant, ... })` from the same file — don't force it through `<button>`. (Genuinely bespoke controls — tabs, dropdown triggers, icon toggles, modal close-X, hero translucent buttons — intentionally stay as raw elements.) Buttons render **sentence case** (`--btn-text-case: none` in both themes overrides DaisyUI v3's uppercase default) — write labels as "Save changes", not "Save Changes"/ALL CAPS.
- **Confirmations** — use `useConfirm()` from [`ConfirmDialog.tsx`](src/components/ConfirmDialog.tsx), never `window.confirm`/native `confirm()`: `const confirm = useConfirm(); if (!(await confirm({ title, message, confirmLabel, cancelLabel, danger }))) return`. Title states the action ("Delete this review?"), buttons name it ("Delete review" / "Keep it"), `danger: true` for destructive. Pass `input: { label, placeholder?, required? }` to replace `window.prompt` — it then resolves the typed `string | null` instead of a boolean. More generally (ux-microcopy): buttons say what they do (verb + object), errors say what happened + what to do (no jargon, no "!"), toasts are one line with no redundant "successfully", placeholders show format not instructions. **No em dashes in user-facing copy** (2026-08 humanize sweep) — use a period, comma, or colon instead; the standalone "—" empty-cell placeholder in tables is the one exception.
- **Z-index** — use the semantic scale from `tailwind.config.js` (`zIndex`): `z-behind < z-content < z-header < z-dropdown < z-overlay < z-sidebar < z-modal < z-toast < z-skiplink`. No arbitrary `z-[...]` values.
- **Rating stars & review presentation (2026-08 premium pass)** — gold via the theme-aware `text-rating` token (mapped to the DaisyUI warning channel); stars are flat by design (the old `.star-shadow` drop-shadow was removed — don't reintroduce it). Numbers next to stars get `tabular-nums`. Trust rules (Baymard-derived): an **average is never shown without its review count** ("4.8 · 132 reviews"); unrated entities say "No reviews yet" (never "NEW"/"N/A"); the profile's ratings histogram is [`RatingDistribution`](src/components/RatingDistribution.tsx) — bars are clickable star filters (radio + click-again-to-clear, shared `starBucket()` mapping) and the whole summary is **hidden at ≤5 reviews**. Review cards are elevated `bg-base-100 border` surfaces (never sunken wells — reviews are the product), metadata is honest (date, "· edited" when meaningfully updated, "Anonymous student"), and anonymous reviews are **never linked across teachers** (fingerprint-privacy line, migrations 019–021). Badging needs evidence: "Top rated" requires 4.5+ AND 10+ reviews; one badge max, no "Popular"/"100+ Reviews" pills; rank markers are plain tabular text, not stickers. **The thresholds, the histogram minimum, and the review-count wording live in [`lib/reviewStandards.ts`](src/lib/reviewStandards.ts)** — components (`TopRatedBadge`, `RatingDistribution`, `ReviewCard`) and the `/how-reviews-work` prose all render from those constants, so change them there and nowhere else. Review cards are the shared [`ReviewCard`](src/components/ReviewCard.tsx) (`compact` for the modal) — never fork the markup per surface. **[/how-reviews-work](src/pages/HowReviewsWork.tsx) documents these mechanics publicly** (limits, thresholds, what moderators can/can't do, what isn't verified) — when a mechanic changes, update that page in the same commit; an out-of-date transparency page is worse than none.
- **Motion** — duration/easing tokens (`--duration-*`, `--ease-*`) in [`src/styles.css`](src/styles.css), JS mirror in [`src/utils/motion.ts`](src/utils/motion.ts), keyframes/animation classes in [`src/styles/animations.css`](src/styles/animations.css). Reuse these; don't inline `@keyframes` in components. The global `prefers-reduced-motion` block neutralizes all animations. There is deliberately **no global transition rule** (the old `* { transition-colors 300ms }` was removed 2026-08): theme switches flip instantly, and only interactive elements (`a/button/input/…` selector in styles.css) carry a standing 150ms transition — don't add `*`-scoped transitions back.
- **Type & spacing** — custom `fontSize` scale (`xs`–`8xl`, line-height/tracking baked in), `maxWidth` tiers (`reading/content/wide/page`), header-clearance spacing tokens (`header`, `header-mobile`). Avoid arbitrary `[..px]` values; round to the scale.
- **Shared primitives** to reuse: `FormInput`/`FormTextarea`/`FormSelect` (RHF forms), `SearchInput`/`Select` (plain controlled filter bars), `PageHero`, `StatTile`, `EmptyState` (always pass an `action` — no dead ends), `ErrorState` (human copy only, never raw `error.message`), `SectionHeading`, `ActiveFilterChips`, `RatingStars`, `RatingDistribution`, `AvatarImage`, `Skeleton` (+ `TeacherList`/`InstituteList`/`ReviewList` variants), `Pagination`, `ToastContainer` + `useToast`, `useIsAdmin` (never call `isAdmin()` ad hoc in components).
- **Icons** — internal [`icons.tsx`](src/components/icons.tsx) (heroicons-outline paths, `aria-hidden`, sized via `className`). No icon npm package (bundle-size call); no inline `<svg>` for a path that already exists there; no Unicode glyphs (`←`/`→`/`↗`/`×`) as icons.
- **Typography & headings** — page H1 = `text-3xl md:text-4xl font-bold` (home display hero exempt); section headers via `SectionHeading` (accent-bar style, `as="h2"|"h3"`); keep heading levels sequential — no h1→h3 skips. Page width caps use the `maxWidth` tiers (`max-w-page` at shell level — not `max-w-7xl`). Headings and labels are **sentence case** ("Student reviews", not "Student Reviews") — swept app-wide 2026-08.
- **Display face (2026-08 identity pass)** — **Newsreader** (editorial serif, self-hosted display cut instanced to opsz 72 / wght 500–700, ~40 kB; regeneration command in [styles.css](src/styles.css)) is the identity face at display sizes ONLY; Inter keeps all UI/body duty. Every `h1` gets it automatically via a base rule; `SectionHeading`, the modal teacher name, `StatTile` values and the profile's big average opt in with the `font-display` utility (weight 600 for section-level, 700 for h1s). **Frank Ruhl Libre** supplies Hebrew glyphs in the same stack, `unicode-range`-scoped so it downloads only when a heading contains Hebrew — bilingual names render as two harmonized serifs. Newsreader's default figures are tabular lining, so big numerals need no extra CSS. Tracking comes from the type scale only — there is deliberately no separate serif tracking knob. Don't use `font-display` below `text-xl`, and don't add a third face.
- **Backdrops** — modals use `bg-scrim/60 backdrop-blur-sm`; the drawer overlay is `bg-scrim/50`. `scrim` is a dedicated theme-aware token (`--scrim` RGB triple per theme in `tailwind.config.js`) that dims in BOTH themes — never use `neutral` for overlays: dark mode defines `neutral` as a light chip color, so `bg-neutral/60` used to *brighten* the screen behind dark-mode modals.
- **Heroes are quiet surfaces (2026-08 premium pass)** — the saturated `bg-primary` slab hero (and its `primary-content`-alpha inner surfaces) was retired: page/profile/modal headers are standard `bg-base-100 border border-base-300 shadow-sm` surfaces (`PageHero` is the shared primitive). Violet is spent only on **small meaningful marks**: the logo tiles, `bg-primary/10 text-primary` icon tiles/monograms, `ring-primary/20` avatar rings, links, the `SectionHeading` accent bar, and primary buttons. Don't reintroduce brand-color slabs — accent *coverage*, not hue, is what reads template-y.
- **Loading states** — route-level Suspense keeps the `PageLoader` spinner; ALL in-page data regions use skeletons from [`Skeleton.tsx`](src/components/Skeleton.tsx) (no layout-shifting spinners). Page `<title>`s: App sets `titleTemplate="%s | TeacherRank"` — pages emit just the page name (the home page opts out with its own template). **Import `Helmet` from [`components/Meta.tsx`](src/components/Meta.tsx), never from `react-helmet-async` directly** (only `HelmetProvider` comes from the lib): the wrapper sets `defer={false}` because the default rAF-deferred head commit never runs in hidden tabs, leaving ctrl+click-opened tabs with the generic index.html title — and the prop only works on the emitting instance. `pageTitles.test.tsx` enforces the import rule.
- **URL state (listing pages)** — TeacherListing's filters/sort/page live in the URL (`search/institute/dept/city/sort/page`, defaults omitted); debounced search writes with `{ replace: true }`, filter changes push, and React Query keys must not change shape (request-count gate: home 4 / institute 3 / profile 2, zero idle/refocus refetches). **Search is never hidden**: the hero shows the open `SearchInput variant="hero"` (hidden search measurably suppresses use), facets sit in an always-visible horizontal toolbar on desktop with department/city appearing only once an institute is chosen, and only mobile folds the facet selects behind the single "Filters" disclosure — search and sort stay exposed there too. Applied-filter chips + the result count render directly above the grid.

- **Multilingual content (2026-08: Hebrew-speaking users)** — user-authored text is any-script: validation regexes use `\p{L}` + Hebrew punctuation (geresh ׳ / gershayim ״ / maqaf ־), never `a-zA-Z` (see `validation.ts`). Naming convention: teacher `name` is bilingual for non-Latin teachers — `שרה לוי (Sarah Levy)` — so ILIKE search matches either script; **institute/city/designation stay canonical English** (they're filter facets — a Hebrew variant of an existing school creates a duplicate facet; normalize via the admin "Edit & Approve" flow). `FormInput`/`FormTextarea` and user-content display elements carry `dir="auto"` for bidi correctness — keep it on new ones. Admin request cards translate inline via Chrome's on-device Translator API (Google Translate link as fallback; content fields only — requester PII stays out of third-party URLs), and "Edit & Approve" auto-prefills the English: name becomes the bilingual form, facet fields get translated with the original shown beneath, and the institute input suggests existing canonical names. Known gap: `profanityFilter.ts` moderation is English-only.

- **Forms & flows** — password fields rendered via `FormInput` get a built-in show/hide toggle automatically (don't add your own; no separate "confirm password" field). Pre-fill known values for signed-in users (`useUser()` → email/name) instead of asking again. Reviews: the comment is optional for 3★+ and required only for ≤2★ ([RatingFormEnhanced.tsx](src/components/RatingFormEnhanced.tsx) + `ratingSchema`). Prefer progressive disclosure (an "Add more details" toggle, filters that appear once an institute is chosen) over showing every field/option at once.

- **Performance** — already in good shape (route code-splitting via `lazyWithRetry`, gzip+brotli, hashed-asset `immutable` + HTML no-cache headers in `vercel.json`, 300ms-debounced search, memoized cards, transform-only animations). Keep it: above-the-fold images use `loading="eager"` (e.g. the profile avatar), everything else lazy; `AvatarImage` sets `width`/`height` + `decoding="async"`. Inter has a metric-matched `Inter Fallback` in the font stack ([styles.css](src/styles.css)) to avoid swap CLS. Put resource hints (preconnect/dns-prefetch) in [index.html](index.html) — Vite injects `%VITE_*%` env values there. Monitoring is exactly two pipelines: Vercel Speed Insights (vitals) + Sentry (errors/traces, no Replay, no public sourcemaps). **Sentry must stay dynamically imported** — [`lib/sentry.ts`](src/lib/sentry.ts) is the only module allowed to touch `@sentry/react`, and it does so via `await import()` inside `initSentry()`, which [main.tsx](src/main.tsx) calls under `requestIdleCallback`. Deferring only the *init call* (which is what this said before 2026-07-30) does nothing: a static import puts the SDK in the entry graph and Vite preloads it — that was 70 kB gzip, a third of first load, on every visit. `logger.ts` and `ErrorBoundary.tsx` import `captureException` from `lib/sentry` and are in the eager graph, so that export stays synchronous and queues until the SDK lands. Also destructure the dynamic import (`const { init, … } = await import(…)`) rather than holding the namespace — a namespace import is opaque to Rollup and can't be tree-shaken (43 kB gzip vs 128 kB). Initial payload is ~140 kB gzip; check `dist/index.html`'s `modulepreload` list after bundle changes. Caveat: `fetchPriority` (camelCase) isn't honored by React 18.3 — use lowercase `fetchpriority` if ever needed.

- **Data layer (post scale-hardening, 2026-07)** — teacher listings go through the `get_teachers_with_stats`/`get_teachers_count` RPCs ([useTeachersOptimized.ts](src/hooks/useTeachersOptimized.ts)) with **no client-side fallback** — on error show the retry card, never re-fetch whole tables. `teachers.avg_rating`/`ratings_count` are denormalized columns maintained by a DB trigger (migration 012) — read stats off the teachers row (or the `teacher_aggregates` projection view), never aggregate `ratings` client-side. Home stats come from the `get_platform_stats()` RPC. Rate limiting is DB-enforced (BEFORE INSERT triggers, migration 015); `src/lib/rateLimit.ts` is a UX pre-check only, and `src/lib/dbErrors.ts` maps trigger/constraint errors to friendly copy. The service worker was removed deliberately (stale-shell incident) — [main.tsx](src/main.tsx) has an unregister killswitch, deletable ~2026-08. Don't add polling `refetchInterval`s; facet/stats hooks cache 15–30 min.

- **Responsive / mobile** — already strong (mobile-first Tailwind, drawer nav + 44px hamburger, bottom-sheet `TeacherModal`, `auto-fit` `.card-grid`, 16px inputs, `env(safe-area-inset-*)`, viewport meta with `viewport-fit=cover`). Conventions: full-height sections use `min-h-dvh`/`h-dvh` (never bare `100vh`/`min-h-screen` — mobile chrome clips it); a global `img,svg,video,canvas { max-width:100%; height:auto }` net lives in [styles.css](src/styles.css); wide tables get the desktop-table (`hidden md:block`) + mobile-card (`md:hidden`) pattern (see Dashboard "My Ratings" and TeacherManagement); size in `rem`/`%`/`clamp`, not fixed px.

- **Cognitive load** — favor recognition over recall and forgiving input. The teacher forms (Add/Edit/Request) suggest existing **Institute / City / Designation** via `<datalist>` — pass `options={…}` to `FormInput` (it renders the datalist), sourced from `useInstitutes()`/`useCities()`/`useDesignations()` in [useTeachersOptimized.ts](src/hooks/useTeachersOptimized.ts); still free-text. URL fields are forgiving — auto-prepend `https://` via `z.string().transform(normalizeUrlInput).pipe(z.string().url())` ([validation.ts](src/lib/validation.ts)). **Do not use `z.preprocess` for this** — it makes the field's input type `unknown` and breaks `useForm<T>` typing with `@hookform/resolvers`; the `.transform().pipe()` form keeps the input type `string`. Long forms chunk core vs optional with a `<div className="divider">` (see Add/Edit teacher forms + the Feedback request form).
